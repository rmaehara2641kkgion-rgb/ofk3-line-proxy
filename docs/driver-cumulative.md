# ドライバー別配送データ 累計データ作成モード

ドライバー別画面の「累計データ作成」で、累計Excel（基準）に週次のドライバー別配送データ（追加、複数可）を加算し、新しい累計Excelを出力する。

- コア: `driver-cumulative-core.js`（解析・統合・出力モデル。DOM非依存） / `driver-cumulative-xlsx.js`（書式付きxlsx生成） / `driver-cumulative-ui.js`（画面）
- 既存の通常集計（`handleDriverDataUpload` / `driver-ability-import-core.js`）と経験値データ処理は変更していない。
- テスト: `npm run test:driver-cumulative`。実データ回帰は `DRIVER_CUM_SAMPLE_DIR=<xlsxを置いたフォルダ>` を付けて実行（実データはGitに入れない）。

## 計算定義
| 項目 | 定義 |
|---|---|
| 加算 | 稼働日数・総稼働時間・配送個数・参考配送個数(全日)・距離・回収/誤配回収/正配依頼合計（簡易版は対応項目） |
| 個/時間 | 累計配送個数 ÷ 累計稼働時間（週別効率の平均はしない。時間0は0） |
| 誤配率 | 累計正配依頼合計 ÷ 累計配送個数(集計対象日)。配送個数0は0 |
| 配管率 | 各ファイルの稼働日数による加重平均（簡易版も同様）。片側が空欄なら値のある側を保持。重みが0で算出不能なら空欄 |
| 空欄 | 0と区別。加算は両方空欄なら空欄、片方のみ数値ならその値 |

## 二重計上防止
統合済み週・ファイルSHA-256・統合履歴（JSON）を出力の「検証・算出方法」シートに記録し、次回の基準として読み込む。
週・日付範囲の重複、同一内容ファイルの再追加はエラーで停止する。履歴のない累計（従来ファイル）は対象期間の記載のみで判定できるため、利用者の確認（チェック）を必須とする。
同じ週を差し替える場合は、その週を含まない累計を基準にして修正後の週ファイルを追加し直す。
