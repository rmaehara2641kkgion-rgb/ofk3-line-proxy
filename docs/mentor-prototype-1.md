# Mentor稼働確認 Prototype 1

Scheduling UI と Mentor の2サイトで、当日の Mentor 起動状況を見る画面。OFK3 マスタは所属の補助であり、この画面の照合には必須ではない。

## 完成した機能

- 通常画面「Mentor稼働確認」に、現在Active候補、当日終了履歴あり、未起動疑い、判定不能の4分類を出す。
- Scheduling が未取得・取得失敗・15分超過のとき、画面上部に取得案内を出す。Mentor 側も同様に案内する。未取得の間、4分類は「—」とし、氏名は出さない。
- 未起動疑いと判定不能に、Mentor 登録名の候補を出す。管理者が同一人物、別人、保留を選べる。登録の解除もできる。
- 管理者が確認した ID 対応は、拡張機能の `chrome.storage.local` キー `ofk3MentorIdentityLinks` に保存する。

## 4分類の判定条件

開始時刻を過ぎた人だけを数える。開始前は一覧に出さない。

- **現在Active候補**: Scheduling と Mentor の識別子が一意に一致し、当日の Active（`shiftEndTime === 'N/A'` かつ `vrmStatus === 'Active'`）がある。または、管理者確認済みの ID 対応が1件で、その Mentor 識別子の当日 Active が1件だけある。表示根拠は「Active確認候補｜管理者確認済みID対応」。
- **当日終了履歴あり**: 一意に照合でき、現在の Active はなく、対象日の終了履歴がある。参考情報であり、起動済みにも点呼完了にもしない。
- **未起動疑い**: 一意に照合でき、現在の Active も当日の終了履歴もなく、対象日全体の履歴範囲が確認できている。未起動の確定ではない。
- **判定不能**: ID 競合、氏名不一致、Mentor 側の識別子競合、取得範囲の未検証、範囲不足、データ未取得、15分超過。

氏名が似ているだけでは分類を変えない。対応関係の登録だけでも Active 候補にしない。

## データ取得条件

- Scheduling と Mentor の両方が取得済みで、どちらも15分以内である。
- どちらかが未取得、取得失敗、15分超過のときは判定を保留する。警告を閉じても保留は続く。
- OFK3 マスタが無くても、上記が揃えば4分類を出す。所属の根拠が無いときは「表示保留」。

## 氏名照合と管理者承認

優先順位は、管理者確認済みの ID 対応、一意な識別子、正規化した氏名、姓名逆転などの表記差、類似氏名である。空白、全角半角、大文字小文字、ひらがなとカタカナは正規化する。漢字の読みは推測して同一人物にしない。

候補が複数、同姓同名、ID 競合のときは自動で1人に決めない。承認前の確認文は「氏名の類似だけでは本人確認になりません。管理者が別の本人情報を確認した場合のみ登録してください。」

保存するのは氏名だけではなく、Scheduling 側識別子、Mentor の staffId と driverId、正式名、Mentor 登録名、状態（同一人物、別人、保留）、登録日時である。1対多と多対1は拒否する。識別子が消えた対応では照合しない。

## 既存点呼機能との違い

点呼要確認一覧と本人対応確認は、これまでどおり OFK3 マスタが必要である。点呼要確認人数は `activeUnseen + after5Unmatched + unknownTime` のままである。開始後5分未満は点呼の猶予として残している。Mentor稼働確認の4分類は、この人数を置き換えない。

## 安全上の制限

- Active 候補は本人確認でも点呼完了でもない。
- 未起動疑いは未起動の確定でも点呼未実施の確定でもない。
- 氏名の類似だけでは本人を確定しない。
- 取得漏れ、遅延、ID 競合のときは安全側で判定を保留する。

## 運用開始手順

1. `chrome://extensions` で OFK3 Cortex Capture を再読み込みする。
2. Mentor のタブを再読み込みし、右上の「Mentor稼働確認」を開く。
3. 警告が出ている間は Scheduling UI で対象日の予約一覧を表示する。開いている場合は、そのページを更新する。
4. 警告が消え、4分類の人数が出てから一覧を見る。
5. 氏名候補は、別の本人情報を確認できたときだけ登録する。

## 既知の制約

- ID 対応はこのブラウザの拡張機能内だけに残る。他の端末や OFK3 サーバへは同期しない。
- 拡張機能の再読み込み後も保存が残ることは、自動テストの設計確認までである。実機の再読み込みでは未確認である。
- 点呼要確認と本人対応確認はマスタ未取得のままでは使えない。
- 詳細診断の折りたたみ内にある「HARVESTへ送る」は、押したときだけ従来の Active スナップショットを送る。

## INO-1・HARVEST 連携時の注意

この画面の4分類は、INO-1 や HARVEST へ自動送信しない。HARVEST へ送る処理は、折りたたみ内の既存ボタンを押したときの Active 生データ送信のままである。Active 候補や未起動疑いを、点呼完了、本人確認済み、未起動確定として連携先へ渡さない。
