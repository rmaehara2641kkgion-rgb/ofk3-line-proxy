## 既知の相違（確認済みの範囲）
1. 判定単位: v1 は「対象日1点」、predict-3 は「全7日窓」。同じ人でも結果の見え方が異なる。
2. 接近の定義: v1 は 49〜60h（過去6日）、predict-3 は窓合計ちょうど 60h。
3. 超過の細分: v1 は確定/予測、predict-3 は窓単位の `exceed` のみ。
4. 当日休・勤務予定未確認: v1 のみ専用区分。
5. 空白セル: v1 と predict-3 は未確認扱いで一致。既存の画面グリッドだけは空白を「休」と表示している（UI 表示のみ、判定は別）。

## 注意（名称についての未検証の推測）
`prefix6` は「過去6日」、`margin11` は「当日の最大勤務（○=11h）分の余裕」を指す可能性があるが、**コードで確認できていない推測**であり、判定には使っていない。

## HARVEST エンジンを入手したときの手順
1. 対象ブランチ/ファイルを取得（Cursor 側で commit・push してもらうか、ファイルを共有してもらう）。
2. `node scripts/rolling-alert-scenarios-report.mjs` で v1 の区分一覧を確認。
3. `node scripts/rolling-alert-scenarios-report.mjs --engine <HARVESTのエンジン.js> --fn <関数名>` で突き合わせる
   （区分名が違えばアダプタで 7 区分に対応付ける）。DIFF/ERROR が 0 件になるまで、どちらを正とするかを業務側と決める。
4. 正規ルールが決まったら `rolling-alert-core.js` の `evaluateDriver` を差し替える、または HARVEST の共有判定を呼ぶ。
   スナップショットの `ruleVersion` が変わるため、保存済みの旧結果は自動的に無効になる（検証で拒否される）。
